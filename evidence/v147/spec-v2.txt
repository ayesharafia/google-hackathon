Uniform branch-aware bracket rule (declared before execution, not fitted)
-------------------------------------------------------------------------
The inherited V135 contract condition is atan2(Ua, Ut) < psi_lower < psi_upper < pi/2, with
Ut = angular_speed * annulus midpoint from the actual decomposition.
Rule, applied mechanically and uniformly to every case:
  branch_a  = atan2(case axial velocity, omega * midpoint_a) for each annulus a, using the
              exact harness decomposition (Fraction boundaries rounded once to float,
              midpoint = inner + 0.5 * width, identical to the request bytes);
  psi_lower = max_a(branch_a) + 0.05 rad   (one declared uniform margin);
  psi_upper = psi_lower + 0.55 rad          (same bracket width as R0's 0.35..0.9).
One bracket per CASE (same for all its annuli). The margin and width are declared constants,
not chosen per case and not chosen to improve convergence. Independent pre-computation on the
exact decomposition admits all 24 declared cases (worst psi_upper = 1.218144 rad < pi/2 at
stress_annuli8); the harness must recompute and print every actual branch angle and bracket
from the request bytes themselves, and refuse to run if any psi_upper >= pi/2 or any
annulus branch >= psi_lower. R0's illustrative branch angles quoted in chat were approximate
and are superseded by these harness-computed values; do not cite chat values.

Refusal classification fix (v2 harness; R0 bytes untouched)
-----------------------------------------------------------
R0 classified preflight-refusal responses as case errors because they carry no evaluation seal
and request_sha256=None. That is BY SOLVER DESIGN (preflight refusal precedes digest/seal).
v2 measurement must classify each response as exactly one of:
  SEALED_VERIFIED        - self-seal and request binding both verified;
  UNSIGNED_REFUSAL_BY_DESIGN - refusal status (e.g. MODEL_INAPPLICABLE/SOLVER_UNSUPPORTED) with
                           verbatim reasons, request_sha256 None, no seal, zero counts, empty outputs;
  HARNESS_FAILURE        - anything else (partial/malformed/unexpected shape).
execution_status fails only on HARNESS_FAILURE or harness errors, never on
UNSIGNED_REFUSAL_BY_DESIGN. Refusal parity/divergence across solvers remains a reported KIND
comparison. Eligibility refusals under v2's branch-aware rule are expected to be ZERO; any
occurrence is reported, not hidden.
