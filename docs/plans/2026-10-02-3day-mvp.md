## 4. The demo case: sphere in uniform flow, Re = 100

### 4.1 Why

Like the poster's flow over a cylinder, it shows separation, a recirculating wake, pressure rise at the front stagnation point, wall shear, and drag. It is cheap, steady and laminar, and has a published drag correlation for comparison.

### 4.2 Case definition (all values are chosen inputs, recorded in the run manifest)

| Item | Value | Source / note |
|---|---|---|
| Sphere diameter D | 1.0 m (centre at origin) | chosen, non-dimensional demo |
| Freestream U∞ | (1, 0, 0) m/s | chosen |
| Kinematic viscosity ν | 0.01 m²/s | chosen ⇒ **Re = U∞D/ν = 100** |
| Density for forces | ρ∞ = 1 (incompressible, kinematic pressure) | `rho rhoInf; rhoInf 1;` as in motorBike `forceCoeffs` |
| Reference area / length | A_ref = π D²/4 = 0.785398 m², l_ref = D | standard sphere Cd definition [STD] |
| Domain | x ∈ [−10D, 30D], y, z ∈ [−10D, 10D] | chosen. Blockage A_sphere/A_cross = 0.196 % (computed) |
| Surface geometry | icosphere, 5 subdivisions = 20,480 triangles | area error −0.030 % vs πD² (computed) |
| Flow model | steady, laminar, incompressible `simpleFoam` | `[VERIFY-IN-BACKEND]` laminar setting in `constant/turbulenceProperties` (`simulationType laminar;`) |
| BCs | inlet: U fixedValue, p zeroGradient · outlet: U zeroGradient/inletOutlet, p fixedValue 0 · sides: slip · sphere: noSlip | `[VERIFY-IN-BACKEND]` names from tutorials |
| Meshes | coarse / medium / fine with **constant refinement ratio r = 1.5** (background `blockMesh` divisions × 1.5 per level, same snappy levels) | GCI needs a constant r [M§15]. Fine target ≤ 2.0 M cells |
| Iteration budget | 3000 iterations cap + residual control | the cap is not convergence [M§32] |
| Reference value | **Schiller–Naumann: Cd = 24/Re·(1 + 0.15 Re^0.687) = 1.09173 at Re = 100** | empirical correlation for spheres, commonly used for Re ≤ ~1000 (Singh et al. 2020 review; Clift, Grace & Weber). A **comparison**, not truth. Report the % difference; do not tune to match |

Measured-rate budget (from §2 numbers): 0.18 M cells ≈ 0.3 GiB, 4 min per 1000 it; 0.6 M ≈ 0.9 GiB, 12 min; 2.0 M ≈ 3.1 GiB, 40 min. Those are extrapolations from two squareBend points, so record the actual values.

### 4.3 Output strategy (no VTK library needed)

- **Native face data for loads (source of truth [M§16]):** `writeFormat ascii; writeCompression off;`. Read `constant/polyMesh/{points,faces,owner,boundary}` and the final-time `p` and `wallShearStress` boundary fields for the `sphere` patch with our own ascii reader. Compute face centres and area vectors with OpenFOAM's method (triangle fan about the point average, area-weighted centroid). The `forces` function object output is the reconciliation reference (0.1 % + abs [M§32]).
- **Slices, lines, streamlines:** OpenFOAM `surfaces` (cutting plane y = 0) and `sets` (line along the wake axis) function objects with a **plain-text format** (`raw`) `[VERIFY-IN-BACKEND: Task D1.3 probes which text formats v2606 accepts]`.
- **Vorticity:** OpenFOAM `vorticity` function object `[VERIFY-IN-BACKEND]`, then sampled on the slice. We never differentiate interpolated slice data ourselves.
