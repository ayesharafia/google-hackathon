# AI settings and chat verification

The owner approved the written design. The implementation uses a separately configured AES-GCM server key and actor/provider associated data, and retains a dedicated settings section beside the project conversation. The existing session-key chat API remains compatible with older callers; the updated browser sends no key in chat requests. The Groq adapter is the only implemented provider.

The agent test suite passed 46 tests with one PostgreSQL integration test skipped. New tests cover encrypted persistence across app restart, missing configuration, request validation redaction, delegated access denial, actor-bound authentication, tampering, model-only changes, deletion and hosted user isolation. Existing tests cover scoped project actions and review. Ruff, JavaScript syntax and whitespace checks passed. SQLite was exercised; a provisioned PostgreSQL deployment was not.

A disposable loopback browser with a synthetic provider key and mocked Groq saved settings, opened the example project, called `design.get`, reloaded, reopened the project without re-entering the key, proposed an eight-minute duration, showed review, applied it, and continued with the recorded result. A second proposal was rejected without changing the draft, and key removal disabled the chat. The first rejection exposed an undefined label; it was corrected and the rejection rechecked. The updated conversation was also inspected at desktop and the settings at 390px width. No real key or real provider was used for this feature test; the earlier real-Groq session reached inspection but the follow-up was rate-limited. No scientific acceptance follows from these tests.

## Interface law review

The new work is an embedded operational workspace, not a marketing page. The hero, footer, pricing, testimonial, logo-wall, illustration and image-seam prescriptions are not applicable to these two sections. The existing application palette and typography are retained rather than introducing unrelated fonts, gradients, glow, decorative icons, badges, shadows, grids, overlays or entrance motion. The settings disclosure, saved status, key/model inputs, save and remove controls use real actions. Conversation messages use restrained tonal separation and legible labels; review values retain their actual table and exact-details disclosure. Text is visible without animation, and the scrollable transcript remains accessible as ordinary content. The phone-width inspection showed readable inputs and margins; desktop inspection showed readable conversation and visible action outcomes. The test clicked save, send, approve, reject, continue and remove; native screen-reader use, native zoom, keyboard-only operation and stop were not separately exercised in this browser pass. Automated tests cover relevant backend behaviors but do not substitute for those manual checks.
