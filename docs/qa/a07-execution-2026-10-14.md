## Findings and corrections

- The legacy endurance script's separate 60-second HTTP and 130-second job waits were unsuitable for the requested smoke bound. The new parent watches from process launch through setup/workload, with distinct cleanup observations and deadlines.
- QA found cleanup pointed at jobs.sqlite rather than the actual hosted projects.sqlite ledger. It was corrected and real queued/running/succeeded ledger fixtures verify cancellation/fencing/preservation.
- QA found execution process IDs and /proc IDs inhabit different namespaces here. Proc-derived monitoring or signalling was therefore unsafe. The new preflight fails closed before Popen or signals instead of guessing mappings. Earlier positive journey receipts with invalid resource-monitor scope are rejected as qualification evidence and are not included as accepted monitored-soak observations.
- Attempted requests are journaled before blocking operations; errors are sanitized. CLI success requires completed target journeys, zero failures, child exit 0, successful ledger cleanup and zero observed owned survivors.
- Owned-process discovery validates start identities; source-path/session/credential/body/exception/PID values are not exposed in receipts. Inherited PHYSIMESH configuration is removed before local synthetic settings are installed. Existing final receipts cannot be overwritten; internal child budgets validate before setup.

Runtime: Python 3.12.14, pytest 9.1.1 and freshly restored Ruff 0.17.0, using available unpinned development dependencies. This differs from pinned Python 3.11.16/hash-locked CI. No historical test pass is reused as a current result.
