## Scope and result

Existing retained export now has a bounded review ZIP endpoint and native
workbench action. It includes exact result/frozen inputs, verified PDF/receipt,
rotor JSON and conditioned raw dependencies, checksum manifest and readable
contents/exclusions. It refuses incomplete or corrupt required evidence.
[Format and use](../technical/study-review-pack.md) describe identities and limits.

The API reuses existing local PDF or hosted report job/cached PDF preparation.
It preserves project/artifact authorization and never calls the capacity solver.
Archives have fixed paths, sorted members, stable timestamps/modes, 128-member/
40 MiB uncompressed bounds, two per-process build slots and private/no-store
responses. The browser verifies project/study/revision/schema/content type and
whole-ZIP SHA-256 before saving. Selection/context changes during headers, job
preparation or body reads cannot download an old package.

Original CSV/XLSX/conversion records, CAD, signatures and executable dependencies
are excluded explicitly. Nothing claims a complete backup, unique original import
lineage, standalone solver replay, authenticated engineering approval or physical
truth. Missing source bytes may prevent a pack while historical JSON stays
readable. Diagnostic unsupported studies preserve their outcome, unavailable
payload and absence of declared sources. No physical formula/tolerance changed.

compares exact frozen snapshot/result/source identities, checks valid PDF bytes
and proves an unsaved draft leaves repeated ZIP bytes unchanged.

API tests exercise actual corruption/missing map/raw dependency/PDF, false source
binding/unsafe digest, small substituted archive budgets, slot saturation, cached
PDF reuse, outsider/cross-project/revoked membership and source-artifact denial.
Removing a source grant refuses the pack even when its digest is known; restoring
it restores access. Report queue idempotency and real fenced publication/accounting
are checked with a deterministic PDF subprocess-output fixture (see limits below).

Browser refusal fixtures alter headers/checksum or return a source refusal; no
production record is changed. A queued-report UI fixture supplies job responses
then downloads the actual package. A hidden organization-change event is
**injected** while controls are disabled to check workspace invalidation; this
is not an ordinary pointer journey. Unit checks cover study changes and delayed
body/context changes separately. Native keyboard disclosure activation passed.

### Failures and limits retained

[First Python run](../../.physicore/evidence/PACK-001-test-20261022192909472872.json)
had 22 passes and two setup failures: realistic example draft version was 2, not
1; and actual worker computation refuses macOS because Linux process controls
are required. Corrected the disposable version and used the existing worker-test
pattern: deterministic producer of a real PDF/receipt, with the actual queue,
fencing, artifact accounting and publication logic. No assertion, physical
reference, gate or tolerance was relaxed. Full Linux isolated computation remains
unexecuted here; the passing fixture does not establish that runtime. Initial
lint findings in the new test's fixture import/lambda were also corrected.

Unexecuted: native browser zoom, screen-reader/real-user usability, PostgreSQL/S3
and production deployment/provider tests, full 40 MiB/128-member load/endurance
qualification, Linux supervisor operation and physical model validation. Budget
refusal tests substitute small caps; slot tests hold permits deterministically.
The 390 px/CSS body zoom=2 runs check document/element containment; CSS zoom is
not native browser zoom. Repeated bytes are tested in one runtime environment.
