# Groq chat verification

The approved first chat slice was implemented locally on `codex/ai-native-foundation`. A fake Groq service was used; no real API key, model request or paid call was used.

Focused Python and affected identity tests: 25 passed (`GROQ-CHAT-001-test-20261027093316651232.json`); includes project scoping, review pause/continuation, stop before a tool call, tampered state, delegated credential denial, bounded provider loop and error redaction. An earlier broader run had 41 passes and one skipped PostgreSQL test because no disposable PostgreSQL service was running. A subsequent direct run including a hosted-viewer chat test passed 26 tests. Existing JavaScript suite: 151 passed. Actual Chrome against a disposable loopback fixture exercised a project read, proposed draft change, approval, rejection, continued chat, credential clearing and storage checks, with no page errors (`GROQ-CHAT-001-test-20261027093343835304.json`). Wheel inspection found the server and browser modules. Ruff and whitespace checks passed.

The first test was deliberately red while the chat module did not exist. A later test failed because its request lacked the newly required run ID; the fixture was corrected and retested. Both receipts are retained. Shutdown by interrupt was an intentional fixture stop.

The interface was inspected at desktop, phone and 2x CSS enlargement. The original review used raw JSON as its primary display; the final design places the actual before/after values in a table and keeps exact JSON in an explicit disclosure. Captures are in `assets/groq-chat/`. The owner design law was reread: new UI follows the established palette and typography, has no decorative gradients, animation, tiles, fake logos or entrance hiding; actual controls and review outcomes were exercised. No claims are made about screen-reader use, native zoom or user testing.

Limits: live Groq model/tool compatibility, provider data handling, production security, load, multi-worker coordination and remote MCP have not been validated. Chat state and stop signals are process-local; restart invalidates conversation state. Stop prevents subsequent tools after the active operation returns; it cannot guarantee cancellation of an operation already underway. Provider socket timeouts and between-step deadline checks are not a hard 60-second interrupt. No equations or scientific acceptance were changed. No publication, deployment or shared-tunnel restart occurred.
