# AI settings

AI settings save each signed-in user's Groq key encrypted in the server metadata database. The server must have a stable, separately managed 32-byte encryption key, supplied as base64 in `PHYSIMESH_PROVIDER_ENCRYPTION_KEY`. Set it in the deployment's secret manager before starting the server; every instance sharing the database must use the same key. Keep it separate from the database and workspace access tokens, restrict its access, and back it up securely. Never commit it or print it in logs. Losing it makes saved provider keys unreadable and users must replace them. Changing it without a migration has the same effect; automatic rotation is not supported.

For a private local installation, an operator can generate the secret into a protected file outside the repository, for example with `umask 077` and `openssl rand -base64 32 > /path/to/private/physicore-provider-key`. Configure the environment from that protected file before starting the application. Do not use the example path literally without choosing an existing private directory. Do not expose this secret to browser users.

Open **AI settings**, enter a Groq key and model, and save. A blank key retains the current credential when updating the model. Use **Remove saved key** to delete it. No call is made to Groq until a chat message or explicit continuation is sent. Prompts and relevant project data are sent to Groq and may incur charges. The chat transcript is page-session only; durable action records are separate. Changing the model starts a new conversation.

In hosted mode, settings are bound to the signed-in user and the existing project permissions apply. Local mode has a single shared workspace identity, so every trusted workspace user can use its saved key and provider allowance. Public access and delegated MCP credentials cannot use saved settings. This is not production security certification; deployment security, access control and secret-manager configuration require separate review.
